## Хэсэг E: Дүгнэлт (debrief)

Хамгийн үр дүнтэй нь **Supermodel** ба **FedEx** аялал байлаа — тус бүр 4 согог олсон:
Supermodel нь апп нээгдэнгүүт ямар ч оролтгүйгээр BUG-01 (тоолуур), BUG-02 (оны формат),
BUG-03 (ногоон Устгах), BUG-04 (эвдэрсэн линк)-ийг илрүүлсэн бол FedEx нэг номын өгөгдлийг
нэмэх → хайх → устгах замаар дагаж BUG-07 (давхардал), BUG-08 (хайлт), BUG-10 (буруу
мессеж), BUG-11 (урт оролт)-ийг олсон. **Couch Potato** 2 согог (BUG-05 хоосон талбар,
BUG-06 хүчингүй он) олсон ч хамгийн ноцтой өгөгдлийн согогууд эндээс гарсан, харин
**Saboteur** ганц BUG-09 олсон боловч тэр нь цорын ганц Critical — API «OK» гэж
худал хариулаад өгөгдлийг чимээгүй гээдэг. Charter-аас гадуур санамсаргүй олдсон зүйл
нь BUG-12: «Нэмэх» товчны латин `x`-ийг нүдээр огт ялгах боломжгүй байсан бөгөөд session-ий
дараа автомат шалгалт товчийг кириллээр олж чадаагүйгээс л илэрсэн; мөн API-ийн гаралтаас
id 4 алга болох, year нь заримдаа тоо, заримдаа мөр байх зэрэг өгөгдлийн тогтворгүй байдал
харагдсан. Шалгагдаагүй үлдсэн нь дараагийн charter болно: Зохиолч талбарын урт оролт,
`<script>` мэт HTML/XSS оролт, Enter товчоор илгээх гэх мэт гарын хэрэглээ, API-ийн бусад
метод (DELETE, PUT) ба дутуу талбартай *зөв* JSON, гар утасны өргөнтэй дэлгэц. Лаб 1-ийн
Playwright автомат тест BUG-01 (мөр ба тоолуурыг харьцуулах), BUG-04 (статус код),
BUG-05, BUG-06, BUG-07, BUG-10 (мессежийн текстийг шалгах), BUG-08 (хайлтын үр дүн),
BUG-09 (API request) зэргийг барих байсан — гэхдээ зөвхөн хэн нэгэн тэр oracle-ийг
урьдчилан бодож assertion болгон бичсэн тохиолдолд. Харин BUG-03 (товчны өнгө),
BUG-02 (тооны формат), BUG-11 (хүснэгтийн зохион байгуулалт эвдрэх) зэргийг хүний нүд
шууд анзаардаг бол автомат тест тусгай CSS/зургийн шалгалтгүйгээр алгасдаг. Эсрэгээрээ
BUG-12-ыг хүний нүд барьж чадахгүй, зөвхөн автоматжуулалт л илрүүлсэн нь хоёр арга бие
биеэ орлохгүй, нөхдөг гэдгийг хамгийн тод харуулсан.
